# htyz.space 迁移指南（换国内服务器 + 备案）

> 起因：现服务器（38.147.185.56，境外）跨境链路丢包严重。
> 实测 180 秒窗口内 **TCP 重传率 22.23%**（正常应 <1%），
> 导致部分用户"页面一直转圈最后超时"。
> 决策：迁移到**国内服务器并完成 ICP 备案**。

---

## 一、为什么必须换，而不是优化

排查结论：**服务器本身没有任何故障**。

| 检查项 | 结果 |
|---|---|
| nginx / 应用服务 | ✅ 正常，本机响应 7–9 ms |
| IP 封禁 | ✅ 无（fail2ban 只封 sshd 的 22 端口） |
| 证书链 | ✅ 完整（4 级，校验 code 0） |
| 连接队列 | ✅ 无溢出 |
| 负载 / 内存 | ✅ 0.06 / 可用 585 MB |
| **跨境链路** | ❌ **重传率 22.23%**，且重传再丢 1507 段 |

问题在"路"上，不在"车"上。同类事实：

- 服务器访问 `1.1.1.1` 仅 3 ms → 服务器出口本身很快
- 用户 IP `223.160.182.10` 访问 `rt=0.004s` → 后端处理极快
- 但整体重传率 22% → **数据包在路上大量丢失**

**因此换服务器必须换"线路"，普通海外 VPS 换了也是白换。**

## 二、备案前置条件（请先确认，可能需 1–3 周）

| 前置项 | 说明 |
|---|---|
| **域名注册商** | ⚠️ `htyz.space` 现注册于 **Hostinger（境外）**。国内备案要求域名在**工信部批复的域名注册服务机构**名单内。**很可能需要先把域名转入国内注册商**（如阿里云/腾讯云），转入本身约需 5–7 天 |
| **域名后缀** | `.space` 是否在批复后缀列表中需确认；若不在，备案无法通过（这是最需要提前确认的一点） |
| **主体证件** | 个人：身份证；单位/学校：营业执照或事业单位法人证书 |
| **服务器** | 必须是**国内**且有资质的云服务商（阿里云/腾讯云/华为云等），且购买时选择支持备案的实例 |
| **网站名称/内容** | 备案时填写的网站名称与内容需合规；校园社区类内容建议以"学校信息交流"表述 |
| **法人/负责人核验** | 需人脸核验或幕布拍照 |

> **建议先在云厂商的备案系统里做"备案预检"**，输入域名即可判断后缀与注册商是否满足条件，避免白准备。

## 三、迁移步骤

### 第 0 步：现在就能做（不依赖新服务器）

现有服务器上已生成并**验证通过**的迁移包：

```
/root/htyz-migration/htyz-migration-20260926-000522.tar.gz   （335 MB）
```

内含：数据库一致性快照、107 个上传文件、应用代码与前端产物、
nginx/systemd/sysctl 配置、`.env`、Let's Encrypt 证书、环境信息与 SHA256 校验清单。

**验证结果**（用脚本实际恢复并启动过）：数据库 `integrity_check: ok`、
112 用户 / 27 表 / 9 视频、健康检查通过、公开接口返回真实数据、视频 worker 正常启动。

> ⚠️ 该包**包含 `.env`（内含 SMTP 授权码）**，传输请用安全通道，迁移完成后删除。

### 第 1 步：新服务器环境准备

```bash
apt-get update
apt-get install -y nginx ffmpeg build-essential python3 curl
# Node.js 18.18+（推荐 20 LTS）
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt-get install -y nodejs
```

### 第 2 步：执行恢复

```bash
# 把迁移包传到新服务器后
bash htyz-restore.sh htyz-migration-20260926-000522.tar.gz
```

脚本会：校验包完整性 → 创建 `htyz` 系统用户 → 恢复数据库与上传文件 →
安装依赖 → 安装 nginx/systemd/sysctl 配置 → 启动服务 → 健康检查。

**它在覆盖已有数据前会要求确认，并自动备份原数据。**

### 第 3 步：签发 HTTPS 证书

```bash
apt-get install -y certbot python3-certbot-nginx
certbot --nginx -d htyz.space -d www.htyz.space --agree-tos -m 你的邮箱

# ⚠️ 必须检查：Debian 的 nginx 未编译 IPv6 支持，
# certbot 若注入 listen [::]:443 会导致 nginx 无法启动
sed -i '/listen \[::\]/d' /etc/nginx/sites-available/htyz
nginx -t && systemctl reload nginx
```

### 第 4 步：域名解析切换（备案通过后才能对外服务）

1. 把 `htyz.space` 的 A 记录从 `38.147.185.56` 改到**新服务器 IP**
2. DNS TTL 建议先调低到 300 秒，便于快速回退
3. 用 `dig +short htyz.space A` 确认解析已切换（各地生效约需旧 TTL 时长）

### 第 5 步：验收清单

- [ ] `curl -I https://htyz.space/` → 200
- [ ] 旧用户能用**原密码**登录（数据库已迁移）
- [ ] 上传一个视频 → 自动转码完成、生成封面、可播放
- [ ] 管理员入口能打开，**校园新闻列表正常**
- [ ] 手机流量（非 WiFi）访问正常
- [ ] 上传的图片历史内容可正常显示

## 四、过渡期怎么办（新服务器就绪前）

已按你的要求**保留现服务器运行**。同时已做的改善：

1. **`tcp_mtu_probing=1`** —— 已在现服务器启用并持久化，
   遇到 PMTU 黑洞的线路可自愈（属保险措施，实测目前未触发）
2. **nginx 访问日志已开启**（此前为 `access_log off`，完全看不到失败请求）
   - `/var/log/nginx/htyz-access.log` —— 主站，含 `rt=`（总耗时）`urt=`（后端耗时）
   - `/var/log/nginx/htyz-unknown-host.log` —— **未知域名访问**（排查"用户用了别的域名"）
   - `/var/log/nginx/htyz-http.log`、`htyz-www.log`
   - 已确认被 `/etc/logrotate.d/nginx` 的 `*.log` 通配符覆盖（每日轮转、保留 14 天、压缩）

**日志判读方法**：

| 日志表现 | 结论 | 对策 |
|---|---|---|
| 完全看不到该用户的请求 | 请求没到服务器 → 线路/封锁 | 等迁移 |
| 有请求，`rt` 大而 `urt` 小 | 网络慢、服务端快 → 线路问题 | 等迁移 |
| `rt`、`urt` 都大 | 服务端慢 | 查应用 |
| 出现 444 | 用户访问的域名不在配置里 | 补 `server_name` |

**已知的一个真实案例**：一个 Clash 客户端用 **IP 直连**请求订阅文件
（`host=38.147.185.56`），被默认 server 块 `return 444` 拒绝。
这是**客户端配置问题**，需把订阅地址改成 `https://htyz.space/...`。

## 五、回退方案

旧服务器保持运行，DNS 指向旧 IP 即可立即回退。

```bash
# 确认旧服务器仍在服务
systemctl is-active htyz nginx
curl -sk -o /dev/null -w '%{http_code}\n' --resolve htyz.space:443:127.0.0.1 https://htyz.space/
```

恢复脚本产生的备份位置：
- 原数据库：`/root/htyz-data-backup-<时间戳>`
- 原 `.env`：`/root/htyz-env-backup-<时间戳>`

## 六、迁移后要做的事

1. **重新执行一次迁移包生成**（数据在切换前还会变化），确保拿到最新数据
2. 在新服务器验证视频转码（`journalctl -u htyz | grep video`）
3. 在旧服务器上**停止对外服务**，避免两个 IP 同时被访问造成数据分叉
4. 关闭旧服务器上不再需要的服务；`xray` 代理端口已迁到 8443，如需保留请另行处理
5. 确认 SMTP 在新环境可用（发一封测试邮件）
6. 配置数据库定期备份（`sqlite3 htyz.db ".backup"` + 定时任务）
